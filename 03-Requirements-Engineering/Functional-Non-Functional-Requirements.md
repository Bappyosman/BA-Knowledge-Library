# ⚙️ Functional & Non-Functional Requirements

Imagine you are building an **online shopping website**. 🛒💻

Before developers start coding, we need to understand:

👉 **What should the system do?**
👉 **How well should the system do it?**

These two questions help us identify **Functional Requirements** and **Non-Functional Requirements**.

---

# 🔵 1. What Are Functional Requirements?

**Functional Requirements** describe:

> **What the system should do.**

In simple words, these are the **actions and features** of the system.

### 🛒 Example: Online Shopping Website

The system should allow users to:

✅ Create an account
✅ Log in
✅ Search for products
✅ View product details
✅ Add products to the cart
✅ Place an order
✅ Make payments
✅ Track orders

These are all **Functional Requirements** because they describe what the system must do.

---

# 👦 Simple Example

Imagine a calculator app. 🧮

Functional requirements might be:

➕ Add two numbers
➖ Subtract two numbers
✖️ Multiply numbers
➗ Divide numbers

These describe the **functions** of the application.

---

# 🔴 2. What Are Non-Functional Requirements?

**Non-Functional Requirements** describe:

> **How well the system should perform its functions.**

They usually describe the system's:

⚡ Speed
🔒 Security
📈 Performance
🛠️ Reliability
📱 Usability
📊 Scalability

---

# 🛒 Example: Online Shopping Website

### Functional Requirement:

> The system shall allow users to search for products.

### Non-Functional Requirement:

> Search results should appear within **2 seconds**.

The first requirement explains **what the system does**.

The second explains **how well it should do it**.

---

# 📊 Simple Comparison

| Functional Requirement | Non-Functional Requirement        |
| ---------------------- | --------------------------------- |
| What the system does   | How the system performs           |
| Features and actions   | Quality and performance           |
| Login                  | Login should be secure            |
| Search products        | Results within 2 seconds          |
| Place an order         | System should handle 10,000 users |
| Make payment           | Payment data must be encrypted    |

# 💻 Software Engineering Example

Imagine we are building an **Online Banking App**. 🏦📱

## 🔵 Functional Requirements

The app should allow users to:

👤 Create an account
🔐 Log in
💰 Check account balance
💸 Transfer money
📄 View transaction history
💳 Pay bills
📱 Receive notifications

These are the functions of the app.

---

## 🔴 Non-Functional Requirements

The app should:

⚡ Load within 3 seconds
🔒 Protect user information
📈 Support 100,000 users
🛠️ Be available 99.9% of the time
📱 Work on Android and iOS
🔐 Encrypt sensitive data

These describe the quality and performance of the app.

---

# 🧩 Types of Non-Functional Requirements

## ⚡ 1. Performance

How fast should the system work?

### Example:

> The system should display the dashboard within **3 seconds**.

---

## 🔒 2. Security

How should the system protect information?

### Example:

> Users must log in using a valid email and password.

> Sensitive payment information must be encrypted.

---

## 📈 3. Scalability

Can the system grow?

### Example:

> The system should support 100,000 active users at the same time.

---

## 🛠️ 4. Reliability

Can users depend on the system?

### Example:

> The system should be available 99.9% of the time.

---

## 👥 5. Usability

Is the system easy to use?

### Example:

> A new user should be able to complete registration without training.

---

## 🔄 6. Maintainability

How easy is it to update or fix the system?

### Example:

> Developers should be able to update the payment module without changing the entire system.

---

## 📱 7. Compatibility

Can the system work on different devices and platforms?

### Example:

> The application should work on Android, iOS, and modern web browsers.

---

# 🛒 Complete Example: Online Marketplace

## 🔵 Functional Requirements

The system shall:

1. Allow users to register.
2. Allow users to log in.
3. Allow sellers to create shops.
4. Allow sellers to add products.
5. Allow customers to search for products.
6. Allow customers to add products to the cart.
7. Allow customers to place orders.
8. Allow customers to make payments.
9. Allow customers to track orders.
10. Allow administrators to manage users and shops.

---

## 🔴 Non-Functional Requirements

The system shall:

1. Load pages within **3 seconds**.
2. Support at least **10,000 concurrent users**.
3. Protect user data using encryption.
4. Have at least **99.9% availability**.
5. Work on mobile, tablet, and desktop devices.
6. Be easy for new users to understand.
7. Recover from system failures within a defined time.

# 🎯 Why Are Both Important?

Imagine an application that has amazing features but:

❌ Takes 30 seconds to load
❌ Crashes frequently
❌ Is difficult to use
❌ Has poor security

Would users be happy?

Probably not.

Now imagine a very fast and secure application that has no useful features.

Would users use it?

Probably not.

So, a successful software product needs both:

> **Functional Requirements = What the system does**
> **Non-Functional Requirements = How well the system does it**

---

# 👨‍💼 Business Analyst's Role

A Business Analyst helps:

🔍 Understand business needs
📝 Identify functional requirements
⚙️ Define non-functional requirements
🤝 Discuss requirements with stakeholders
✅ Make requirements clear and testable
📋 Document requirements for the development team

---

# 📌 Final Example

### ❌ Weak Requirement:

> The system should be fast.

This is unclear.

### ✅ Better Non-Functional Requirement:

> The system should display the product search results within **2 seconds** for at least **95% of user requests**.

Now the requirement is:

✔️ Clear
✔️ Measurable
✔️ Testable

---

> **Functional requirements tell us what to build. Non-functional requirements tell us the standard at which we should build it.**

Both are essential for building software that is not only functional, but also fast, secure, reliable, and easy to use. 🚀

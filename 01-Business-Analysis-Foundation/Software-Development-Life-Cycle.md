# 🔄 SDLC (Software Development Life Cycle)

Imagine you want to build a **house**. 🏠

You would not start by randomly buying bricks and building walls.

First, you would:

1. Understand what kind of house you want.
2. Create a plan.
3. Design the house.
4. Build it.
5. Check if everything works.
6. Give it to the owner.
7. Maintain and improve it.

Software development works in a similar way.

This complete journey is called **SDLC**.

---

# 🔹 What Is SDLC?

**SDLC** stands for:

> **Software Development Life Cycle**

It is a step-by-step process used to plan, create, test, deliver, and maintain software.

### Simple Flow:

**Planning → Requirements → Design → Development → Testing → Deployment → Maintenance**

---

# 1️⃣ Planning

Before building software, the team asks:

🤔 What problem are we trying to solve?
🎯 What is the goal?
💰 How much will it cost?
⏳ How long will it take?
👥 Who will use it?

### Example:

A business wants to build an online marketplace.

The team may ask:

> "Can we build this product with our available time, budget, and resources?"

---

# 2️⃣ Requirements Analysis

Now the team tries to understand exactly what users and the business need.

### Example: Online Marketplace

Users may need:

🔐 Login
🔍 Product search
🛒 Add to cart
💳 Payment
📦 Order tracking

The Business Analyst usually works closely with stakeholders during this stage.

The requirements may be documented using:

📄 BRD
📋 FRD
📝 SRS
👤 User Stories
🔄 Use Cases

---

# 3️⃣ Design

Now the team decides:

> **How will the software work?**

The team creates:

🎨 UI/UX Design
🗄️ Database Design
🏗️ System Architecture
🔌 API Design

### Example:

The team decides:

* What the login page will look like.
* How user data will be stored.
* How the payment system will connect.
* How different parts of the application will communicate.

---

# 4️⃣ Development

Now developers start writing code. 💻

For example:

👨‍💻 Frontend Developer → Builds the user interface
👨‍💻 Backend Developer → Builds the server and business logic
🗄️ Database Developer → Manages data

### Example:

Developers create:

🔐 Login
🛒 Cart
💳 Payment
📦 Order Management

This is where the design becomes a working software product.

---

# 5️⃣ Testing

Now the team checks:

> **Does the software work correctly?**

Testers look for problems called **bugs**. 🐛

They may test:

✅ Login
✅ Product search
✅ Payment
✅ Order placement
✅ Security
✅ Performance

### Example:

The requirement says:

> "A user should be able to log in with a valid email and password."

The tester checks:

✔️ Valid email and password
❌ Wrong password
❌ Empty fields
❌ Invalid email

---

# 6️⃣ Deployment

After testing is completed, the software is released for real users.

This is called **Deployment**.

For example:

📱 Mobile app → Published to an app store
🌐 Website → Made available online
🏢 Business software → Installed in the company

Now real users can use the software.

---

# 7️⃣ Maintenance

The work does not always end after deployment.

The team may need to:

🐛 Fix bugs
🔒 Improve security
⚡ Improve performance
➕ Add new features
🔄 Update the system

### Example:

Users request:

> "Please add dark mode."

The team may add this feature in a future update.

---

# 🛒 Example: Building an Online Marketplace

### 💡 Planning

The business wants to sell products online.

### 📋 Requirements

Users need:

* Registration
* Product search
* Cart
* Payment
* Order tracking

### 🎨 Design

The team designs:

* Homepage
* Product page
* Cart page
* Checkout page

### 💻 Development

Developers build the features.

### 🧪 Testing

The team checks whether everything works correctly.

### 🚀 Deployment

The marketplace goes live.

### 🔧 Maintenance

---

# 👨‍💼 Where Does a Business Analyst Work in SDLC?

A Business Analyst can be involved in almost every stage.

### 📋 Requirements

Understand business needs and document requirements.

### 🎨 Design

Explain business requirements to the design and development teams.

### 💻 Development

Clarify questions from developers.

### 🧪 Testing

Check whether the software meets the original requirements.

### 🚀 Deployment

Support user acceptance testing and release preparation.

### 🔧 Maintenance

Collect feedback and identify new business needs.

# 🔄 SDLC Models

Different teams may follow different SDLC models.

## 💧 Waterfall

Each phase is completed before the next phase begins.

```text
Planning
   ↓
Requirements
   ↓
Design
   ↓
Development
   ↓
Testing
   ↓
Deployment
```

Good for projects where requirements are stable.

---

## 🔁 Agile

The software is built in small cycles called **Sprints**.

```text
Plan
 ↓
Build
 ↓
Test
 ↓
Release
 ↓
Feedback
 ↺
```

Agile allows teams to:

✅ Get feedback quickly
✅ Change requirements
✅ Release features gradually

# 🧠 Simple Real-Life Example

Imagine building a bicycle. 🚲

### Planning

What type of bicycle do we need?

### Requirements

It should have:

🚲 Two wheels
🛑 Brakes
🔔 Bell

### Design

Decide how the bicycle will look and work.

### Development

Build the bicycle.

### Testing

Check:

* Do the wheels move?
* Do the brakes work?
* Is it safe?

Give it to the user.

### Maintenance

Repair it and replace damaged parts.

---

# 🎯 The Main Idea

SDLC helps a team build software in an organized way.

Instead of randomly writing code, the team follows a process:

> **Understand the problem → Plan the solution → Build the software → Test it → Release it → Improve it.**

A Business Analyst is especially important because they help ensure that the team is:

> **Building the right software for the right business problem.** 🚀
